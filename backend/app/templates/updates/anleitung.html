Auf eine neue Version aktualisieren

1. Zuerst sichern

Beim Start der neuen Version laufen Datenbank-Migrationen automatisch. Sichere deshalb vorher, Datenbank und Belege:

docker compose exec db-backup /backup.sh
tar czf storage-$(date +%F).tar.gz storage/

Der Dump landet in ./backups/daily/. Das Verzeichnis storage/ muss separat gesichert werden: Es enthält die Rechnungs-PDFs; ein Datenbank-Dump allein stellt sie nicht wieder her.

2. Den neuen Stand holen

Im Verzeichnis der Installation, dort wo docker-compose.yml liegt. Die Nummer ist die oberste Fassung von der Releases-Seite:

git fetch --tags
git checkout v1.2.3

Wer das Programm nicht mit Git geholt, sondern das ZIP-Archiv entpackt hat, lädt stattdessen das neue Archiv, entpackt es daneben und übernimmt aus der alten Installation die Datei .env sowie die Verzeichnisse storage/ und backups/.

3. Neu bauen und starten

docker compose up -d --build

Nur Herunterladen genügt hier nicht. Der Dienst app wird aus dem Quelltext gebaut, es gibt kein fertiges Abbild in einer Registry. Ein docker compose pull überspringt ihn deshalb wortlos, meldet dabei Erfolg — und die alte Fassung liefe weiter. Der Bau ist der einzige Weg, auf dem neuer Code hineinkommt.

4. Prüfen, ob es geklappt hat

Läuft die Anwendung nach kurzer Zeit nicht wieder, ist die Aktualisierung bewusst abgebrochen worden, statt halb erledigt weiterzulaufen. Sieh nach mit:

docker compose logs app

In diesem Fall spiel die Sicherung aus Schritt 1 zurück und melde dich bei uns. Die Sicherung ist der verlässliche Weg zurück.
